## Inventario previo a la selección de casos

La administración no tiene URL propia: `/` → Abrir ajustes → Cuenta y planificación → Usuarios e invitaciones. `AccountPanel` la monta exclusivamente para `user.role === 'admin'`. El servidor comprueba sesión, rol, cuenta esperada y origen independientemente de esa condición visual.

| Superficie | Acciones existentes / ruta del contrato |
| --- | --- |
| Listas y actualización | `GET /api/admin/users`, `/invitations`, `/share-invitations`; apertura del desplegable, Actualizar y Reintentar |
| Invitación personal | Email, nombre opcional, trial/lifetime, correo cuando está configurado; `POST /api/admin/invitations`; copiar/fallback manual; `/account/activate` |
| Enlaces personales | Reemitir y revocar; `POST /api/admin/invitations/:id/reissue`, `:id/revoke`; estados pending/used/revoked/expired |
| Compartibles | Nombre, 1–10.000 altas, 1–90 días; `POST /api/admin/share-invitations`; copiar; `/account/join`; contador y active/expired/revoked/exhausted |
| Revocación compartible | `POST /api/admin/share-invitations/:id/revoke`; conserva cuentas ya creadas |
| Gestión de cuentas | `POST /api/admin/users/:id/disable`, `/enable`, `/revoke-sessions`, `/recovery`; recuperación por `/account/recover` |
| Acceso cloud | `POST /api/admin/users/:id/lifetime`; trial, lifetime, active y expired; no edición de fechas desde UI |
| Cuenta propia | Se permite cambiar lifetime. La UI no ofrece suspensión, cierre de sesiones ajenas ni recuperación sobre la propia fila |
| Otras rutas accesibles al administrador | `/account/forgot-password`, `/privacy`, login/logout y planificación personal compartidos con el usuario B2C; estas áreas tienen suites propias, no se declara aquí cobertura integral de todo B2C |

No existe editor de roles/promoción de usuarios ni cancelación de suscripciones ajenas en esta UI. Lifetime no concede administración. La lista muestra metadata y acceso, no historiales privados.

## Bugs reproducidos y corregidos

| ID | Antes, evidencia | Cambio y regresión |

| ADM-01 | El input `maxUses` tenía `max=1000`, aunque API/documentación admiten 10.000. ## Levantar un escenario manual y repetir la suite

En este mismo environment los binarios, bibliotecas y PostgreSQL ya están preparados. Desde la raíz del repo:

```sh
source /tmp/klisteni-tools/env.sh
# Terminal 1: esquema nuevo, migraciones, administrador y cinco estados de cuenta.
node scripts/b2c-admin-fixtures.ts
```

```sh
source /tmp/klisteni-tools/env.sh
# Terminal 2: usar el origen exacto autorizado por la fixture.
VITE_APP_MODE=instance \
KLISTENI_PUBLIC_PROFILE_FILE=instance-profile.example.json \
KLISTENI_API_URL=http://127.0.0.1:4188 \
pnpm --filter @klisteniapp/b2c-web exec vite --host 127.0.0.1 --port 4187 --strictPort
```

Abrir `http://127.0.0.1:4187`. La cuenta administradora ficticia es `admin@admin.test`; contraseña de demostración: `B2C-admin-fixtures-only-2026!`. Cuentas iniciales `trial`, `expired`, `lifetime`, `paid` y `disabled` en `@admin.test`, con esa misma contraseña ficticia. Todas las identidades terminan en `.test`; ninguna cuenta/dirección real se usa.

Al detener la API con Ctrl-C se elimina únicamente el esquema creado por ese proceso. No ejecutar fixture manual y suite simultáneamente en los mismos puertos. Detener primero la API/web manual y después:

```sh
source /tmp/klisteni-tools/env.sh
pnpm test:admin
# O un único perfil:
pnpm test:admin --project webkit-narrow
```

Para otro checkout: instalar dependencias del repo con Node 24+ y el pnpm declarado, proveer un PostgreSQL **local y descartable** en `TEST_DATABASE_URL` e instalar Chromium/WebKit con Playwright. La fixture rechaza hostnames externos y no carga `.env` productivos. Se pueden usar los navegadores estándar sin `KLISTENI_*_EXECUTABLE`; los overrides de este environment sólo seleccionan ejecutables locales verificados. El helper de fixtures y el config son reproducibles sin las dependencias embebidas: basta una base local compatible y motores instalados.
