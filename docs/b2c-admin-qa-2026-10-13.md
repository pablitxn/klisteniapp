<a id="inventario-previo-a-la-selección-de-casos"></a>
## Inventory before case selection

Administration has no dedicated URL: `/` → Abrir ajustes → Cuenta y planificación → Usuarios e invitaciones. `AccountPanel` mounts it only for `user.role === 'admin'`. The server independently checks session, role, expected account and origin.

| Surface | Existing actions / contract route |
| --- | --- |
| Lists and refresh | `GET /api/admin/users`, `/invitations`, `/share-invitations`; open disclosure, Actualizar and Reintentar |
| Personal invitation | Email, optional name, trial/lifetime, mail when configured; `POST /api/admin/invitations`; copy/manual fallback; `/account/activate` |
| Personal links | Reissue/revoke; `POST /api/admin/invitations/:id/reissue`, `:id/revoke`; pending/used/revoked/expired states |
| Shareable links | Name, 1–10,000 registrations, 1–90 days; `POST /api/admin/share-invitations`; copy; `/account/join`; counter and active/expired/revoked/exhausted |
| Shareable revocation | `POST /api/admin/share-invitations/:id/revoke`; retains existing accounts |
| Account management | `POST /api/admin/users/:id/disable`, `/enable`, `/revoke-sessions`, `/recovery`; recovery through `/account/recover` |
| Cloud access | `POST /api/admin/users/:id/lifetime`; trial, lifetime, active and expired; no UI date editing |
| Own account | Lifetime changes allowed. UI offers no suspension, revocation of other sessions or recovery on the user's own row |
| Other administrator routes | `/account/forgot-password`, `/privacy`, login/logout and personal planning shared with B2C users; separate suites cover these areas, without claiming complete B2C coverage here |

This UI has no role/promotion editor or cancellation of other users' subscriptions. Lifetime does not grant administration. The list shows metadata/access, not private histories.

## Start a manual scenario and repeat the suite

In the recorded environment, binaries, libraries and PostgreSQL were prepared. From repo root:

```sh
source /tmp/klisteni-tools/env.sh
# Terminal 1: new schema, migrations, administrator and five account states.
node scripts/b2c-admin-fixtures.ts
```

```sh
source /tmp/klisteni-tools/env.sh
# Terminal 2: use the exact fixture-authorized origin.
VITE_APP_MODE=instance \
KLISTENI_PUBLIC_PROFILE_FILE=instance-profile.example.json \
KLISTENI_API_URL=http://127.0.0.1:4188 \
pnpm --filter @klisteniapp/b2c-web exec vite --host 127.0.0.1 --port 4187 --strictPort
```

Open `http://127.0.0.1:4187`. Fictional administrator: `admin@admin.test`; demo password: `B2C-admin-fixtures-only-2026!`. Initial `trial`, `expired`, `lifetime`, `paid` and `disabled` accounts at `@admin.test` use the same fictional password. All identities end in `.test`; no real account/address is used.

Ctrl-C stops the API and removes only its generated schema. Do not run manual fixture and suite simultaneously on the same ports. Stop manual API/web first, then:

```sh
source /tmp/klisteni-tools/env.sh
pnpm test:admin
# Or a single profile:
pnpm test:admin --project webkit-narrow
```

For another checkout, install dependencies with Node 24+ and declared pnpm, provide **local disposable** PostgreSQL in `TEST_DATABASE_URL`, and install Chromium/WebKit through Playwright. The fixture rejects external hostnames and does not load production `.env` files. Standard browsers work without `KLISTENI_*_EXECUTABLE`; environment overrides only select verified local executables. Fixture helper/config need no embedded dependencies: compatible local DB and installed engines suffice.

<a id="checklist-manual-breve"></a>
## Brief manual checklist

1. At 360 px and desktop, open settings/account/administration. Review scroll, fields, rows, states and readability. Check disabled mail and absence of dangerous own-account controls.
2. Invite `amiga@admin.test` with trial; copy/open link in another profile, choose password and activate. Check 15-day trial, regular role and Utilizado row. Repeat with lifetime: invitee must not see administration.
3. Reissue pending invitation: old link stops working. Revoke the new one and check rejection. Create a one-registration shareable link and use two profiles: only one creates an account; the other sees exhaustion.
4. Create a 10,000-registration/90-day shareable link. Check counter, collapse/reopen/reload: list cannot recover the link. Revoke without affecting existing registrants.
5. For a regular user, revoke sessions, suspend, try login, enable and log in again. Complete recovery and confirm retained history.
6. Grant/remove lifetime on expired/trial/paid accounts; check original state restored without role promotion. Switch accounts in two tabs: stale UI must not continue administering.
7. Run lost-response/slow-issuance network tests; never simulate failures with real accounts/destinations. Fixture confirms SQL effects even when the browser loses the response.
